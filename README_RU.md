# HibpGuard — исходники MVP для iOS

SwiftUI, MVVM, async/await, CryptoKit и Keychain. Целевая система — iOS 17.0 и новее. Для открытия проекта нужен Xcode 16 или новее с подходящим iOS SDK. Сторонних библиотек и менеджеров зависимостей нет.

В приложении три вкладки: email, пароль и план действий. Настройки API-ключа открываются кнопкой с шестерёнкой. Используются системные компоненты SwiftUI, светлая и тёмная темы, Dynamic Type и подписи для VoiceOver.

## Запуск в Xcode

1. Распакуйте архив и откройте `HibpGuard.xcodeproj`. Создавать новый проект или вручную переносить исходники не требуется.
2. Выберите схему `HibpGuard` и доступный симулятор iPhone. Если симуляторов нет, установите iOS runtime через настройки Xcode.
3. Нажмите Run (⌘R). Для проверки паролей требуется интернет.
4. На вкладке email по умолчанию включено «Демо». Введите `example@example.com`: появится вымышленная утечка. Для пустого деморезультата используйте `clean@example.com`. Ни один из этих демозапросов не отправляется в сеть.
5. На вкладке пароля введите `password` и нажмите кнопку проверки. Ожидается ненулевой счётчик; точное число со временем меняется.
6. Откройте «Действия», отметьте пункт и перезапустите приложение. Отметка должна сохраниться.

## Реальная проверка email

Для произвольных email нужен собственный платный ключ HIBP. Откройте настройки приложения, вставьте ключ и сохраните его, затем выберите режим «HIBP API». Формат ключа проверяется локально, действительность — при запросе.

Ключ хранится в Keychain с `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, без синхронизации. Адрес целиком передаётся HIBP по HTTPS. Приложение не сохраняет email, результаты email-проверки, пароль или его хэш.

Для тестового сетевого запроса без платной подписки документация HIBP предусматривает ключ `00000000000000000000000000000000` и адрес `account-exists@hibp-integration-tests.com`. Это ограниченный тестовый доступ, а не ключ для проверки произвольных адресов.

Число 0 означает «не найдено в базе», а не «надёжен». Для полного списка полей утечки запрос содержит `truncateResponse=false`. Парольный запрос использует `Add-Padding: true`. Ответ 404 считается пустым результатом только в email-проверке; 403 может означать несколько причин отказа. См. [документацию HIBP](https://haveibeenpwned.com/API/v3).

## Если у вас Ubuntu или Windows без Mac

Редактировать Swift-файлы можно в любом редакторе. Xcode требует macOS. В архиве есть ручной workflow `.github/workflows/ios-check.yml`, который запускает сборку и XCTest в симуляторе на macOS runner GitHub.

1. Создайте пустой GitHub-репозиторий.
2. Из распакованной папки `HibpGuard` выполните:

   ```bash
   git init
   git branch -M main
   git add .
   git commit -m 'Add HibpGuard iOS MVP'
   ```

3. Скопируйте адрес своего репозитория из GitHub. В следующей команде замените значение переменной этим адресом:

   ```bash
   hibp_repo_url='ВСТАВЬТЕ_АДРЕС_СВОЕГО_РЕПОЗИТОРИЯ'
   git remote add origin "$hibp_repo_url"
   git push -u origin main
   ```

4. На GitHub откройте Actions → iOS simulator checks → Run workflow.
5. Откройте job `test` и шаг `Build and run XCTest on an installed iPhone simulator`. Успешный запуск означает, что проект собрался и тесты прошли в выбранной среде. Этот workflow ещё не запускался автором проекта.

Workflow не использует Apple ID или HIBP-ключ и не обращается к реальному API: сетевые ответы в XCTest подменены. В приватных репозиториях выполнение может расходовать включённый лимит GitHub Actions и оплачиваться сверх него; проверьте условия своего аккаунта.

Проверка в симуляторе не создаёт установочный файл для iPhone. Для установки на телефон нужен отдельно собранный и подписанный device build. Сборка для симулятора для этого не подходит.

## Запуск на iPhone через Mac

1. В Xcode выберите проект → target `HibpGuard` → Signing & Capabilities.
2. Укажите свой Team и уникальный Bundle Identifier, оставив автоматическую подпись.
3. Подключите iPhone, подтвердите доверие и выберите его устройством запуска.
4. Следуйте запросам Xcode о сопряжении и Developer Mode, затем нажмите Run.

Для macOS-сборки в CI с последующей установкой нужны собственные signing certificate и provisioning profile. В этот MVP не включены чужие сертификаты, автоматическая передача Apple ID или неподписанный IPA под видом установщика.

## Автоматические тесты на Mac

В Xcode: Product → Test (⌘U). Или из корня проекта:

```bash
bash Tools/test_on_simulator.sh
```

Скрипт сам выбирает UUID доступного iPhone-симулятора. Результат XCTest сохраняется в `build/*.xcresult` на машине сборки. Все 27 тестовых методов используют тестовые значения. Ни один тест не проверяет ваш настоящий email или пароль.

## Границы этой версии

Исходники подготовлены как MVP. В среде подготовки нет Xcode: компиляция, XCTest, SwiftUI previews и поведение на реальном устройстве здесь не проверены. Выполнены разбор синтаксиса Swift, проверка структуры Xcode-проекта и вспомогательных файлов; подробности в `VALIDATION_RU.md`.

Публичный выпуск требует иконки приложения, настройки подписи, проверки интерфейса на устройствах и заполнения сведений о приватности в App Store Connect. Если вы планируете оплачивать один ключ за всех пользователей, запросы с этим ключом следует перенести на свой backend. Эта версия предполагает личный ключ каждого пользователя.
