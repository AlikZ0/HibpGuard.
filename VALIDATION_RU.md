# Проверка HibpGuard

## Что выполнено при подготовке

- Все Swift-файлы разобраны Swift-грамматикой Tree-sitter без синтаксических ошибок. Это не проверяет типы и доступность API Apple.
- `project.pbxproj` прочитан независимым парсером OpenStep/Xcode. Проверена связность ссылок на исходники, таргеты и схему.
- Проверен XML общей схемы, синтаксис shell-скрипта, структура YAML workflow и Python-генератор проекта.
- Проверена целостность ZIP и присутствие исходников, инструкции и тестов.
- Отдельными HTTP-запросами проверены публичный пример Pwned Passwords и официальный тестовый email HIBP: оба вернули 200; известный пароль найден, полный email-ответ содержит поля, которые ожидает модель. Использованы только публичные тестовые значения. Это проверка контракта API, не запуск Swift-кода приложения.

Компиляция Swift, сборка Xcode, 27 тестов XCTest, превью SwiftUI и визуальная проверка на iPhone не запускались: в среде подготовки нет Xcode и SDK Apple. Утверждать, что приложение уже собрано и протестировано на iOS, было бы неверно. Workflow GitHub Actions включён в исходники, но не отправлен в ваш репозиторий и не запущен.

## Что покрывают добавленные XCTest

| Файл | Проверки |
|---|---|
| `PasswordPrivacyTests.swift` | Известный SHA-1-вектор; сохранение пробелов, регистра и UTF-8; CRLF; padding; отсутствие совпадения; повреждённый ответ |
| `NetworkingTests.swift` | URL-кодирование email; полный JSON; нужные заголовки; только префикс в password URL; 404 для разных API; 401/403/503; 429; таймаут; отмена; Retry-After |
| `ViewModelTests.swift` | Очистка поля до ответа; отбрасывание устаревшего результата; уход в фон; ошибка сети; пустой ввод; переключение деморежима |
| `StorageTests.swift` | Чтение, обновление и удаление тестового Keychain-элемента; атрибут доступности; JSON; сохранение отметок; ошибка записи; неизвестные ID |

В сетевых тестах используется `RecordingTransport`. Нужды в платном ключе и обращении к HIBP нет. Keychain-тест создаёт отдельный элемент с уникальным service ID и удаляет его после проверки.

Запуск на Mac:

```bash
bash Tools/test_on_simulator.sh
```

Или Product → Test в Xcode.

## Ручная проверка после сборки

1. В режиме «Демо» проверьте `example@example.com`, затем `clean@example.com`. Должны появиться вымышленная утечка и пустой деморезультат. Подпись демонстрации должна быть видна в обоих случаях.
2. Переключитесь на HIBP API без ключа. Приложение должно предложить добавить ключ, а не показать чистый результат.
3. Добавьте официальный тестовый ключ и тестовый адрес из README. Убедитесь, что отображаются название, дата и типы данных.
4. Проверьте пароль `password`: ожидается ненулевой счётчик. Поле должно очиститься сразу после запуска запроса. Не сверяйте результат с фиксированным числом, база меняется.
5. Отключите интернет и повторите password-проверку. Должна появиться ошибка подключения, без сообщения «не найден».
6. Запустите проверку и быстро отмените её. Загрузка должна завершиться, поздний ответ не должен показать результат.
7. Введите пароль и сверните приложение. При возврате поле должно быть пустым. Повторите с черновиком API-ключа.
8. Отметьте действия, закройте и откройте приложение. Отметки должны сохраниться. Проверьте сброс.
9. Включите светлую и тёмную темы, увеличьте системный размер текста. Проверьте маленький iPhone и iPad; поля, кнопки и список должны оставаться доступны. Прокрутите длинные ошибки и названия утечек.
10. Включите VoiceOver. Проверьте названия полей, подписи кнопок и состояние галочек.

Обработку 429 проще проверять добавленным XCTest с подменённым ответом. Не создавайте искусственную нагрузку на HIBP ради получения ограничения.

Перед публикацией проверьте реальную подпись, Keychain на физическом устройстве, privacy-поля App Store Connect и требования к иконке. Keychain может сохранять данные после удаления приложения; используйте кнопку удаления ключа, если хотите его убрать.
